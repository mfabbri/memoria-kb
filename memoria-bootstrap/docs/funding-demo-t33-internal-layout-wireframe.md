# T33 - Wireframe layout interno

Stato: artefatto interno di composizione e revisione, non pubblicabile.

Questo wireframe traduce il brief `funding-demo-t33-internal-layout-brief.md`
in una base concreta per l'impaginazione delle sei schermate. Non contiene
immagini, estratti o dati storici copiati nel repository. I materiali visivi
sono solo riferimenti da aprire nel data root esterno durante una revisione
autorizzata.

## Sistema visivo comune

- Formato: 16:9, una idea principale per schermata.
- Struttura: fascia superiore per titolo e stato, area centrale per contenuto,
  fascia inferiore per provenance o domanda aperta.
- Gerarchia: titolo breve, una frase guida, massimo tre elementi visivi.
- Stato fisso nel footer: `INTERNO · REVISIONABILE · NON PUBBLICABILE`.
- Non usare numeri di bando, importi, nomi di finanziatori o promesse di
  completamento.
- Per ogni immagine o scansione usare un riquadro con etichetta
  `RIFERIMENTO ESTERNO`, senza incorporare il materiale nel repository.

## Schermata 1 - Il problema

```text
+------------------------------------------------------------------+
| 1 · IL PROBLEMA                                  STATO: INTERNO  |
|                                                                  |
|       Il patrimonio documentale esiste, ma resta difficile       |
|       da ricomporre e verificare.                                |
|                                                                  |
|       [ fonti diverse ]  ->  [ percorsi frammentati ]             |
|                                                                  |
|       Una frase di chiusura: prima di raccontare una storia,      |
|       bisogna rendere visibili tracce, lacune e verifiche.        |
|                                                                  |
| INTERNO · REVISIONABILE · NON PUBBLICABILE                       |
+------------------------------------------------------------------+
```

Nota di impaginazione: usare una composizione astratta, senza schermate di
prodotto o documenti reali. Il contrasto deve essere fra frammentazione e
percorso verificabile, non fra prima/dopo commerciale.

## Schermata 2 - Il patrimonio

```text
+------------------------------------------------------------------+
| 2 · IL PATRIMONIO                                STATO: INTERNO  |

| [ FONTI ] -> [ DOCUMENTI ] -> [ EVIDENZE ] -> [ RICONCILIAZIONE ]|
|                                                                  |
|  persone       luoghi          eventi          decisioni visibili |
|                                                                  |

|  e alternative.                                                   |
|                                                                  |
| INTERNO · REVISIONABILE · NON PUBBLICABILE                       |
+------------------------------------------------------------------+
```

Nota di impaginazione: diagramma semplice a quattro nodi. Le parole sono
categorie di lavoro, non claim storici né risultati pubblicabili.

> Cinque storie come punto di partenza. Me.Mo.Ri.A mette in relazione
> informazioni su persone, luoghi, documenti ed eventi provenienti da fonti
> diverse, che usano criteri e linguaggi non omogenei, per costruire un
> percorso di ricerca chiaro e verificabile.

## Schermata 5 - Cosa dimostra e cosa non dimostra

```text
+------------------------------------------------------------------+
| 5 · LIMITI                                      STATO: INTERNO   |
|                                                                  |
|  MOSTRA                         NON DIMOSTRA                      |
|  metodo e primi risultati      biografie concluse                |
|  piste da verificare           pubblicazione automatica           |
|  dubbi visibili                fatti senza fonti e review         |
|                                                                  |
|  La validazione umana resta il passaggio che chiude una ricerca.  |
|                                                                  |
| INTERNO · REVISIONABILE · NON PUBBLICABILE                       |
+------------------------------------------------------------------+
```

Testo approvato da mantenere integralmente nella versione impaginata:

> Il lavoro mostra un metodo e primi risultati. I suggerimenti del motore e
> la revisione degli storici aprono nuove piste e indicano nuove fonti da
> verificare. Un ciclo di ricerca si chiude solo quando le fonti disponibili
> sono state confrontate, le decisioni documentate e lo storico ritiene
> concluse le verifiche prioritarie. Dubbi e lacune restano visibili; nessun
> contenuto diventa pubblicabile senza fonti tracciabili e validazione umana.

## Checklist di consegna interna

- [ ] Le sei schermate rispettano l'ordine dell'entrypoint.
- [ ] I testi approvati delle schermate 3 e 5 sono integrali.
- [ ] La schermata 4 usa tre riferimenti esterni e conserva la domanda aperta.
- [ ] Ogni schermata mostra lo stato interno/non pubblicabile.
- [ ] Non sono stati copiati immagini, estratti o dati storici nel repository.
- [ ] Non compaiono bando, importo o finanziatore.
- [ ] Non sono stati applicati `ProfilePatch`, creati verified facts canonici o
  modificati profili canonici.
